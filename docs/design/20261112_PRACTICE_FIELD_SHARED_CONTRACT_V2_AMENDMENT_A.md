## A. From the framework chat

| # | Note | Amendment |
|---|---|---|
| F1 | An agent-authored idea has no list or version; "accept" must create them, through the framework's builder, with a new origin `practice_field`, a server list marker and an evidence kind citing the idea's result and evidence packet. After acceptance the list's newest version must be `ready`. A nomination that was an existing idea version creates the next version on that same list. | **§8 is amended.** T3 never writes a list or a version itself. | F2 | Horizons and lines map 1:1 onto the idea record. | **§4 gains the mapping.** Slot `short` / `medium` / `long` = `horizonEnum` `swing` / `positional` / `longterm` (`HORIZON_WINDOW_SESSIONS` 10 / 30 / 60). A wrong-if line = an invalidation condition `{ symbol, side: 'below', level, basis: 'daily_close' }`; the contract's `completed_session_close` and the record's `daily_close` are one basis, and the contract uses the record's word from here on. |

| F4 | Battle `chatExchanges` and workshop exchanges carry no exchange id at `c37baa0d`; only the Forge research hosts do. | **§5.1 and §6 are amended.** In release 1 the citation of a conversation is the evidence packet's bounded excerpt plus its content hash, never an exchange id. | F5 | Refs and reuse. | **§5.2 is amended:** a nomination citing an idea version uses the shared ref `{ watchlistId, hypothesisVersion }` with `contentHash` optional. **§6 is amended:** for a Trend Follower book, an entry's evidence packet may cite ID-1's `setupEvidence` snapshot (`{session}__{SYMBOL}__{ruleKey}`) instead of a second price read; the importer is added to that store's import guard deliberately, in T1b. |
