## §1. Findings

### F1 — Revalidate the stored source inside a new nomination transaction

**P1 · Criterion 8 · CONFIRMED.** `api/_utils/filmRoom/cardStore.js:385` and `api/film-room/card.js:256`.

After ownership/replay/version/stage checks, `nominateCard` checks the book and immediately builds the nomination. Neither the handler nor the transaction reads the card's source battle/tape or checks its exact stored moment. This differs from create's transactional source verification at `api/_utils/filmRoom/cardStore.js:322` and `api/film-room/card.js:145`.

**Reproduction:** use the real close writer to produce the stalled ACN moment, file a Watch card through the real card handler, then remove `tags.items` from its stored tape. Send a **new** nominate op with the card's current version and an active synthetic idea book. The response is 200, the entry becomes nominated, and its nomination record exists. Marking the day unavailable or deleting the tape produces the same result. Removing the moment after the nomination transaction has read the entry also commits successfully. The tape is absent from the transaction read set, so its change creates no conflict. Unit probes additionally changed tape/battle ownership and battle agent; these too were not revalidated, although no real ownership-changing workflow was assumed.

**Refutation:** this is not a replay of a nomination already committed. It is the first nomination of a previously filed Watch card. BC-3 allows offering a Watch card later, but the request expressly extends criterion 8's stored-moment/unavailable-day/race restrictions to nomination. No accepted reading exempts a new nomination. The defect reproduced on the real Firestore emulator, not only the in-memory store.

**Fix proposed, not made:** after the successful-replay branch, transactionally validate the filed source's battle ownership/attribution and its tape's coverage, exact moment, situation version and archetype before either nomination write. Reuse the existing source checks through an injected transaction verifier so the store does not acquire a tape/model dependency. A changed or unavailable source must refuse with the corresponding existing source error. Preserve successful lost-answer replays even after the source changes. Add moved-range and removed-moment transaction-race tests alongside unavailable/deleted/foreign-source tests; assert neither half writes on refusal.

**Evidence:** `evidence/c1Review.probe.test.js` F-SOURCE/F-SOURCE-RACE rows; `evidence/c1IndependentReview.rules.mjs` first four rows; Linux independent unit/emulator reports.

### F2 — Validate the builder's identity and initial state before committing either half

**P2 · Criterion 12 · CONFIRMED under the requested malformed-builder injection.** `api/_utils/filmRoom/cardStore.js:344`, `:335`, `:390`.

`nominationDocOf` returns the replacement builder's object without validating its source tuple or initial state. Both Offer create and nominate commit that object while independently writing a queued nomination copy on the actual card.

**Reproduction:** keep the default builder's entire output but change only `source.entryId` to `absent-entry`. Both paths return 200. The actual card is nominated and points to the record; the record points to `absent-entry`, which does not exist. A second probe changes only the builder's top-level state to accepted: the book says accepted while the entry copy says queued. These behaviors reproduced on the emulator. A separate reviewer independently reproduced the wrong-entry association.

**Refutation and scope:** Firestore did **not** commit only one physical document. Atomicity works; the association between “the record” and **its** entry is wrong. Criterion 12's pairing must include the source reference, or a record naming any nonexistent entry would satisfy it merely by sharing a transaction with some other card. The default builder is correct, and a client cannot inject a builder. This is a boundary failure under the exact replacement-builder attack requested, not a claim of a present client exploit or a spontaneous default-builder failure. Unlike accepted A-11, malformed returned objects are committed successfully rather than throwing and writing nothing.

**Fix proposed, not made:** before either write, validate a plain nomination object with `state: 'queued'`, source kind and the exact entry/situation/question/version tuple supplied to the builder, plus valid required clock/history fields. Preserve Practice Field-owned extra fields; validate the shared invariants rather than duplicating its whole schema. Reject malformed output with neither half written. Pin both paths, source mismatch, state mismatch, missing fields, invalid instants, and a valid extra-field control. Continue mapping calendar failure to 503.

**Evidence:** wrong-source/wrong-state rows in the independent unit and emulator probes; independent refutation in `evidence/amendment-review.md` and `amendment-census-results.json`.
