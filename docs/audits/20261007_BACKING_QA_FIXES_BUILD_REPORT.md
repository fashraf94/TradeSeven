## 3. BUG-001 — the cause, verified (lines at the base `8ce61c3d`)

Fable's read was correct on both counts.

- **Desktop keeps the control mounted:** `src/components/League/backing/BackingDesk.jsx:250` `const staking = view.kind === 'stake' && card != null;` and `:304` mounts `<StakeControl …>` with no key for as long as `staking` holds.
- **The control owns the receipt:** `src/components/League/backing/StakeControl.jsx:139` `const [result, setResult] = useState(null);` and `:194` `if (result) { … }` renders the "Backed" receipt from that state. Nothing outside the control can clear it.
- **Add changes nothing:** the card's button (`src/components/League/backing/TeamCard.jsx:266–267`, `data-backing="cta-back"`, `onClick={onBack}`) calls the desktop screen's `onToStake` — `src/components/League/backing/BackingScreen.jsx:239` `setView((v) => ({ ...v, kind: 'stake' }))`. The kind is already `'stake'`, so `staking` stays true, the control is not remounted, and `result` survives: the receipt stays.
- **Why the workaround worked:** "Back another team" calls `onClose` → `onToCard` → kind `'card'` → `staking` false → the control unmounts; the next "Back" mounts a fresh one. The pod list's `onOpenSeat` does the same (`BackingScreen.jsx:238`).
- **Mobile is unaffected:** `BackingScreen.jsx:280` (`view.kind === 'card'`) and `:298` (`view.kind === 'stake' && cardQuery.card`) are mutually exclusive on `view.kind`; the Add button lives on the card view (`:290` `onBack={() => setView(… kind: 'stake')}`), so when it is pressed no stake control is mounted, and the stake view mounts a fresh one.

## 8. Flags for the founder, in plain words

2. **The pretend teams are now named by their agents.** With item E the pod list and every label read "Smoke Scout" / "Smoke Sentry" (the player's name beside it), and the receipt reads "Backed · 100 BP on Smoke Scout". That is the real product behaviour for a seat with an agent; the runbook was rewritten to match.
3. **The strip after a refund (item G's read-only answer).** In a real week a viewer whose only pod was refunded will see "Last week banked / Your stakes have settled". The one-line fix is in §4-G; it was not built, as instructed.
4. **A smoke agent and the operator scripts.** The five whole-collection scripts (§5) would list a smoke agent if run while a smoke pod is live. None runs on its own and each is dry-run or read-only by default; `cleanup` before Sunday remains the rule.
5. **The receipt's allowance line on a replay.** A replayed Confirm (the same request twice) gets no balance from the server; the receipt then shows the line only once the wallet snapshot carries the stake's debit, and nothing before — the FAB-10 posture, by design.
6. **A behaviour change on the desktop seam, by the prescribed design (R1-5).** Because every "Back" / "Add" now mounts a fresh control, pressing the card's button a second time while a FORM for that seat is open discards what was typed (a custom amount, a chosen preset, ticked attestation boxes). Before the fix that press did nothing. The only way to keep the form while still replacing a receipt is the receipt special case the ask forbade, so this stands; a request in flight is protected (R2-2).
7. **The trainer record** has the same namespace gap as the private record did (§4-F), unobservable in a smoke — and during a smoke the "As a team" tab beside "Your record" stays on the production record (the runbook says so).
8. **The my-stats reply gained two keys** (`namespace`, `productionPoolsSkipped`). No client reads them; they exist so a browser tester can see which record they are looking at.
