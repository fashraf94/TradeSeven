### 1.3 Readings recorded at the gate (no source conflict; stated so the review can check them)

1. **The sweep's global gate.** Spec §3 says global `off` returns before any calls I/O and §8 scopes every transition to a battle resolved `on`; neither names global `shadow`. A battle can resolve `on` only under global `on` (§3's table), so the sweep branch runs only when the global mode is `on` and returns before any read at `off` **and** at `shadow`. At global `on` with an empty allowlist every battle resolves `off` — the sweep reads queue/cursor rows to discover and skip each one (Amendment B §10) and touches nothing else, which is the frozen state B.10 describes.
2. **The reconciliation route's index.** Spec §8 allows "existing index or a named new single-field index". No `agentBattles` composite carries `expiresAt`; the route pages `agentBattles` on `expiresAt >= now − 7d` ordered by `expiresAt, __name__` — served by Firestore's automatic single-field index — and filters `status ∈ {active, completed}` in memory. No `fieldOverrides` entry is added for `agentBattles.expiresAt`: an override REPLACES the automatic single-field set for that path, and other queries order by it.
3. **The queue index.** The traversal's two queries (`nextExpiresAt > 0` ordered by `nextExpiresAt, __name__`; `nextExpiresAt == null` ordered by `__name__`) use the automatic single-field index. It is declared explicitly in `firestore.indexes.json` as a `fieldOverrides` entry for `callSweepQueue.nextExpiresAt` carrying exactly the automatic triple (ASC, DESC, CONTAINS at COLLECTION scope — the `tickBodies.expireAt` pattern), so the deployment contract names it and the pin test can check it; deploying it is a no-op against the automatic index.
4. **`supersedes` at off.** Spec §6 calls the stamp "ordinary state" and Amendment B §3 scopes it to an ordinary filing that replaces a **call-family** slot. The shared writer stamps it only when the replaced slot is call-family; an ordinary-over-ordinary replacement writes exactly today's bytes.
5. **Per-battle rate limit.** `applySecurityMiddleware`'s limiter keys on the client (`api/_utils/rateLimit.js:22`), not the battle. The endpoint keeps that limiter and adds a process-local per-battle window (20 per 60 s), the index-memo precedent (per warm instance).
6. **Battle-document shape.** `createAgentBattle` writes no `directive` key (`agentBattleService.js` has none); the slot is written only by chat.js and file-directive.js, and Release 2 already added fields inside it additively (`adjustmentId`, `canonicalTextVersion`). The call fields are the same kind of additive nested change; no top-level battle key is added. The thread exchange's `supersedes` and `callId` are additive fields on an existing array element (the `archetypeGate` precedent).

Nothing above is a STOP.

### 10.3 Questions and readings for the framework chat (recorded, not decided here)

1. **Amendment B §12, the "until" wording.** The hold template is `Hold off on the ${symbol} ${entry|exit} until ${until}.` where `until` is the §4 deadline phrase with its leading preposition removed (`by today's close` → `today's close`; `by the next check` → `the next check`; `before the battle ends` → `the battle ends`; `by 15:30` → `15:30`) — `callActions.js:49-54`, pinned in `callActions.test.js:86`. The amendment gives the template with `${deadline}`; this is the builder's reading of how a `by …` phrase reads after `until`. If the chat prefers the phrase verbatim (`until by today's close`) or a different surface, the change is one template line plus its pin.
2. **Amendment B §10's wording vs the sweep at per-owner off** (review #18). The sweep runs only at global `on` (gate reading §1.3.1); at global `on` with an empty allowlist it reads each queue row's PARENT battle document (the owner and the status live only there), pages `agentBattles` by `expiresAt` in the reconcile phase, and writes the `callSweepState` cursor once per invocation — and transitions nothing, writes no call / receipt / event / battle. B.10's sentence ("may read `callSweepQueue` / `callSweepState` rows … reads and writes nothing else for it") should name the parent read, the reconcile page and the cursor write before blessing.
3. **The reconciliation route's index** is the automatic single-field index on `agentBattles.expiresAt` (reading §1.3.2); no `fieldOverrides` entry for `agentBattles` is added because an override replaces the automatic set and other queries order by it.
4. **A pick's slot traded for the other option** (review #15). Spec §2's "affected leg" rule was argued for shots; for a pick the request IS the selection, so this build records a present result other than the selected swap as `no_matching_trade` — with the committed trade and the selection named ("The agent exited KO for AMD at the 10:30 check — not the selected JPM") — and retires the `call_pick` directive when its swap-out left the book (`heard.js:100-103`). Reversible in one line plus its rows if the chat rules otherwise; without it the case is silent and the dead directive blocks other call-family filings until its lifetime.
5. **`saidOk` on the `declared` event** (review #14). Spec §10 lists it in the shape; this build sets it to the lint verdict over the declared calls' own wording (true when every `said` passes, false when any fails, null when none was said). The verifier's alternative — drop the field, since §4's display gate is computed at read time and one boolean cannot carry several calls' verdicts — is the chat's to choose; the field is additive either way.
6. **The 1a text's wording** (review #21) is exactly D minus the two sentences spec §3 prescribes, hash-pinned. Read as the model reads it, two of its claims are inaccurate under 1a: "Go or Hold off" names two answers that are acknowledgements (go on an act-default call, hold on a hold-default call) while `go_now` — which does file a directive — is unnamed; "sees each one as a tile in their cockpit" (and the player-ask's "shown to the player") describe a screen Build 2 brings. Round 3 re-qualifies the text; this is wording input for it, not a build change (a change would re-pin the hash).
