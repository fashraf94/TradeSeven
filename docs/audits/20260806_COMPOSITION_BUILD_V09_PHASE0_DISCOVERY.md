## §C · Items 1–14 — detailed findings

### Item 1 — Compiler cell-read contract — **AMEND**
`compileBuild.js` consumes verdicts from `userBuildDelta.compatCells[ruleId]`, shaped `{state, via, treatment?, zone1Ref?, tensionReason?}` (`compileBuild.js:26,156,187`). **The compiler does not import the compat map** — the *caller* supplies the cells. It distinguishes explicit-vs-default by **one field**: `if (!cell || cell.via === 'fallthrough')` → `compat_cell_missing`, skip (`:188`); `via:'fallthrough'` **is** absence (A-4 / §5.6 no-invented-defaults). State→verdict map: `neutral→compatible`, `native→native`, `tension→tension`, `core_conflict→core_conflict`; anything else → `unknown_compat_state` (`:196`). **The compiler already understands `tension`** as a first-class verdict and requires a `treatment` on it (`:226`; schema `archetypeBuildSchemas.js:42`) — so adding tension is a **source/adapter change, not a compiler change.** The live source never emits it: `COMPAT_STATES=['native','neutral','core_conflict']` (`archetypeRuleCompatibility.js:66`).

**Adapter seam:** `compileOnSettingsChange.js:85` `resolveEquippedCompatCells` maps `getRuleCompatInfo(snap.sourceRef, archetype)` into `compatCells` keyed by `snap.id` — the authored cell-matrix registry drops in behind this same interface (or behind `getRuleCompatInfo` itself, which both the settings-writer and the injectable gate route through). **AMEND the spec:** of the authored fields `{state, rulingIds, advisory, narrowedParams, displayReason, notes}`, only `state` maps directly; `advisory→treatment` (`advisoryDowngrade`), `displayReason→tensionReason`; `narrowedParams/rulingIds/notes` have no compiler consumer and need a stated mapping or a contract extension. Naming nit: the live export is `ARCHETYPE_RULE_COMPATIBILITY`, not the spec's `ARCHETYPE_COMPATIBILITY`.

### Item 2 — §5.4/§5.5 fixture semantics — **AMEND**
"41 P2 fixtures" = **41 executed test cases** in `compileBuild.test.js` (31 plain `it()` + one `it.each` over 8 `BINDING_DESCRIPTOR_FIELDS` + one over 2 no-op types = 41; corroborated by `20260723_ARCHETYPE_P2_14a_PHASE_REPORT.md:16`), **not** fixture builders (`compilerFixtures.js` has 5 rule builders + `buildDelta`). Class invariants under an adapter: **core_conflict ⇒ illegal pair** (explicit `blocked:true` verdict + `blockedControls`, `validation.pass` stays true — `:214`); **missing ⇒ absence ⇒ gate red** (`compat_cell_missing`/`metadata_missing` are validation errors — `:174`); **mismatch keeps meaning** (binding differing in any of 8 descriptor fields stays `prompt_advisory` with `bindingMismatch`, no coercion). **Critical correction:** the compiler emits **no `deferred`/`non-offerable` token**; its only explicit non-offerable outcomes are `core_conflict` and `ruleModeGate` blocks (`:239`). B1's "deferred ⇒ explicit complete-but-non-offerable verdict" is honored *in spirit* by the two blocked classes but under different names — a semantically distinct `deferred` verdict is **net-new compiler work.**

### Item 3 — narrowedParams ↔ guardrailBinding + save layer — **AMEND** (confirms "both")
`guardrailBinding.valueParamKey` does pure scalar extraction: `value = snapshot.paramValues[key]`, `typeof value === 'number'` else `binding_value_unresolved` (`compileBuild.js:264`); the binding matches 8 exact descriptor tokens against 3 supported shapes (`matchSupportedShape :106`) — **none encodes a range/domain**. ### Item 4 — identityHash CI lock + coexistence — **AMEND** *(crux — CONFIRMED)*
`computeIdentityHash()` hashes `{definitions, corpus}`, stripping only version constants; `getArchetypeDefinition().compat = ARCHETYPE_RULE_COMPATIBILITY[codeId]` survives via `...rest` (`archetypeRegistry.js:120,152,157`) — so **the compat map is already a first-class hashed input of `identityHash`.** Repo-wide grep for `compatHash` (any separator/case): **zero hits.** Replacing the map therefore changes `identityHash` **by construction**, auto-tripping the CI lock — no new hash to author; only the spec wording needs correcting. **Lock mechanics:** `archetypeRegistry.test.js:102-110` reads the single current-version snapshot (`SNAPSHOT_PATH` from `ARCHETYPE_IDENTITY_VERSION`, `:48`) and asserts `computeIdentityHash() === snapshot.identityHash`; run in CI via `tests.yml`. **Coexistence:** shipped model is **deferred-regeneration singleton** — only `archetype-registry-identity-v1.json` exists; `getArchetypeDefinition(codeId)` takes no version arg and always stamps the current version (`:84`); `compileBuild.js:147` hard-fails any non-current `parentIdentityVersion`. No runtime path resolves two identities. **The current lock most naturally extends to the CATALOG model** (its artifact is already an immutable per-version committed file; a catalog loads two), whereas the live regeneration path structurally can hold only one. **Closure-sheet choice required** (test A33).
