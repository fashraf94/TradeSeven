### 2.4 The bagger event source

**What is persisted, per snapshot.**

- `agentBattle.thresholdHistory[symbol] = { maxMultiplier, minMultiplier }`, written every evaluate tick as `scoreUpdate['thresholdHistory.{symbol}'] = score.history` (`api/cron/agent-evaluate.js:893-900`; dot-path per symbol so a swap's zero-reset earlier in the same run survives, `:895-899`). The value is the FENCED scorer's `effectiveMax = max(historyMax, highChange / baseATR, multiplier)` (`api/_utils/agentScoring.js:276-283`, returned as `history` `:297-300`) — monotonic within a day, and it takes the tick's intraday HIGH, so a crossing that reversed before the tick is still recorded.
- `scoring.thresholds[symbol].threshold` = `baseATR`, a percent of price (`AgentBattleScreen.jsx:624`, `:741`); the tier multiples are `THRESHOLD_MULTIPLIERS.bagger = 1.0` (`src/constants/baggerBombScoring.js:43-44`; `computeProximity.js:21-30` keeps a local copy of the same table — §8).
- Per tick: `evaluations[].scores.{active, banked, total}` (`agent-evaluate.js:2652-2656`); `scoreState.{activeScore, bankedScore, currentScore, lastScoredAt}` (`:876-882`); `trades[].lockedPoints` (banked = the sum, `:867-869`; the client sums the same field, `:931-935`); badge points bank nightly into `scoreState.bankedBadgePoints` (`:870-874`).

Battles are `fullday` (`agentBattleService.js:35`; D-61), so the reset never runs during a live battle today; the derivation must still treat a DECREASE as a re-seed, never a crossing.

**What the client renders today, and from what.** `enrichAsset` (`:724-854`) merges the persisted history with the LIVE multiplier: `history.maxMultiplier = max(persisted, live)` (`:805-809`). That merged `history` drives the row's badges (`calculateAssetScoreV3` `:827-833` → `BadgeRow` `TacticalRow.jsx:454-459`), the proximity `achievement` text (`computeProximity.js:244-246` ← `highestCrossed` `:56-58`; rendered by `ProximityLabel.jsx:41-48`; `ACHIEVEMENT_CONFIG.bagger` = `💣 BaggerBomb!` `:34`), the fuse's lit segments and its own 400 ms "ignite" brightness flash on a newly lit segment (`ChamberFuse.jsx:333-349`), and `ChamberFuse.onThresholdCross` (`:310-331`), which fires when the LIVE multiplier crosses a tier — threaded through `TacticalRow.jsx:46` and `:471` but **never passed by the screen** (dormant). So today the row's tag can light from a websocket price up to a full cron tick BEFORE the persisted crossing exists, and un-light if the price falls back before the tick — the live half of the merge is the current value, not a running max (`:807`).

**Can "crossed into bagger between two snapshots" be derived from persisted scoring state alone, and once?** **Yes.** Per player symbol: `prev.thresholdHistory[sym].maxMultiplier < THRESHOLD_MULTIPLIERS.bagger` ∧ `next.thresholdHistory[sym].maxMultiplier ≥ THRESHOLD_MULTIPLIERS.bagger`, comparing two snapshots of the subscribed doc (`src/hooks/useAgentBattle.js:28-32`, `onSnapshot`). It is a client-side comparison of two PERSISTED values — the case the seed accepts. Once-per-crossing follows from monotonicity; never-on-mount follows from seeding the per-symbol last-seen value on the doc's FIRST snapshot without firing — the `useLandingKey` idiom (`landing.js:64-84`: seed when the doc is present, fire on a change only; a timer that only ENDS, `:86-92`). Session state: a ref map `{ [symbol]: lastSeenMaxMultiplier }` in the screen or its hook; `sessionStorage` is used nowhere under `src/screens/` and is unnecessary — a reload re-seeds from a doc that already reads `≥ 1.0`, so it cannot re-fire. A swapped-in symbol arrives with a zero-reset entry (`agent-evaluate.js:895-899`) and seeds at 0. A symbol swapped OUT keeps its history entry (the cron never deletes; `agent-daily-scores.js:76-78` calls them "stale") — the derivation iterates the CURRENT book, not the history map.

**The moment's four parts and their sources.**

- The burst: one-shot on the row wrapper (`:1503-1512`, where `LandingWash` already mounts per row at `:1506`), keyed on the crossing; `bouncy` or `fade` through `motionToken`; ≤ 700 ms (`LANDING_TOTAL_MS`, `landing.js:29`); `useReducedMotion` is already in the screen (`:494`).
- The `BAGGER` tag: the row ALREADY shows `💣 BaggerBomb!` and a `bagger` badge from the live-merged history. The seed's tag on the persisted crossing would be a second, differently-sourced tag for the same fact — a §9 two-sources hazard (hazard 37). **§4 #7.**
- The footer `Bagger hit · {mult}× banked`: `{mult}` is ambiguous — the ATR multiple crossed (`1.0×`, the persisted fact `maxMultiplier ≥ 1.0`) or the row's conviction tier multiplier (`2× / 1.5× / 1×`, `CONVICTION_MULTIPLIERS`, a constant keyed by the row's tier — the arena mock renders `TIER_META[tier].mult`, i.e. `1.5×` on a Core row). "Banked" is true of the tier's bonus in the persisted sense (the history is monotonic and the bonus banks nightly, `agent-evaluate.js:870-874`). **§4 #8.**
