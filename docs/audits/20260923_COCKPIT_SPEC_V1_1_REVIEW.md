### R2-1 — A fresh parent read does not make publication atomic with completion

**Spec section:** §3.5(2-3), §3.10(2,4). **Severity: P1, Build 0.** **Round 1:** R-4. **Contract:** §3 publication and §6 terminal-parent priority; do not weaken either.

**Evidence — VERIFIED:** Spec:57-58 explicitly separates a `WriteBatch` of creates from its preceding parent read. Completion reads the parent inside `db.runTransaction` at `api/cron/agent-evaluate.js:5699-5708` and writes its update at `:5895`. Publishing after `:4058` fixes the failed-before-evaluation-commit orphan, but does not serialize publication with that later completion.

**Failure sequence — inferred:** publication reads `active`; completion commits `completed`; publication's unconditioned create batch lands. Build 1's completion scan may already have finished, leaving a new open call under a terminal parent. Spec:80 only tests completion before the phase's read, which misses this ordering. A timed-out batch that commits late can take the same route.

**Fix as written:** “Publish the declarations record and all its calls as one atomic create-once commit in a transaction that reads the parent and checks `status === 'active'` and the committed evaluation identity. The parent read participates in the transaction's conflict check. Completion and mint must serialize. Freeze the candidate payload, timestamps and ordinals once outside transaction retries. On an existing publication, compare the entire expected immutable document set using a defined canonical representation, excluding mutable state/response/outcome fields; exact identity is idempotent success and any mismatch is `call_conflict`. An identical retry must never reset a hit or response. Add a fixture where completion commits after the publication parent read but before its commit, plus a late-timeout variant. Calls-phase failures stay isolated.”

### R2-2 — Four seconds of remaining handler budget is not four seconds available to calls

**Spec section:** §3.5(1,4), §3.6, §3.10(5). **Severity: P1, Build 0.** **Round 1:** R-3, R-1. **Contract:** §3 aggregate deadline and preservation of completion reserve.

**Evidence — VERIFIED:** Spec:56 reserves 4,000 ms before the model but permits the phase whenever at least 4,000 ms remain at the final commit. HEAD admission is 10,000 + 22,000 + 12,000 = 44,000 ms (`api/_utils/agentEvalTransport.js:14-15,36,167-176`); the cron invokes it at `api/cron/agent-evaluate.js:2371`. Narrations remain ahead of capture and are not remaining-budget gated (`:4090-4104`). Post-call validation, execution and the final update occur between model completion and this new phase, so a one-time pre-call reserve cannot establish the late balance. Capture itself can yield below its floor (`api/_utils/tickCapture/captureWriter.js:493-494`).

**Failure sequence — inferred:** arrive at `:4058` with 4.1 seconds of the 290-second budget left and a narration queued. Spec admits four seconds of calls, leaving approximately 0.1 seconds of soft budget before the always-dispatched narration and capture tail. The extra ten-second platform buffer is not a reserve the new phase may deliberately consume. The numbers are a counterexample to the predicate, not a measured timeout.

**Fix as written:** “Set `callsReserveMs = mode === 'off' ? 0 : 4_000`; use the existing admission helper with the existing 12,000 ms post-call allowance plus this reserve. This makes the nominal model admission threshold 48,000 ms only in shadow/on and leaves 44,000 ms at off. At actual phase entry, compute `available = remainingHandlerBudget - protectedTailReserve`; run only if `available >= 4_000`. Define that reserve for the chosen placement and preserve the existing narration/completion allowance; do not treat the platform kill buffer as available. With a conservative 12,000 ms tail reserve and placement immediately after the commit, the late minimum is 16,000 ms, not 4,000. Keep anticipation and capture's existing gates and explicitly report any coverage they forfeit. All reads, canonicalization, retries, creates, flips, reference additions and the phase-status attempt share one absolute deadline. No new work is dispatched after expiry. A timeout is unconfirmed; a final status write is best-effort within the same budget and may itself remain unknown. Test late reserves with narration queued and every slow phase component.”

Adding the admission reserve may defer a model call that would have fit the old threshold. Report that as an intentional shadow/on scheduling effect of Spec:56, never as proof that enabling declarations has no effect on model admission.
