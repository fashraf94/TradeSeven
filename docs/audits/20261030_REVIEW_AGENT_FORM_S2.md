### Should-fix

**S2R-2 — `fuseFormLayout.js` is reached flag-off and sits outside the bundle guard row.**
`FuseHero.jsx:50` and `ArenaMobile.jsx:27` import it statically and read it only inside `AGENT_FORM_LEAGUE_ENABLED` ternaries, so with the flag off Rollup drops it only while it has no module-level side effect. The S1 review's SR-3 row, `agentForm.flagOffBundle.test.js:44-49`, bundles each flag-off-reached module as the graph reaches it and asserts nothing is left; its `REACHED` list gained `leagueAgentFormSlot.jsx` this build but not `fuseFormLayout.js`. Evidence: a plant of `export const FUSE_FORM_KEYS = Object.freeze(Object.keys(FUSE_FORM_PX));` (the exact shape of SR-3's leak) **survived** the bundle row, `agentFormFlags.test.js`, `fuseFormLayout.test.js` and `agentForm.guard.test.js` (snapshot tree, Windows), and a Linux flag-off build of the planted head differs from the head's in **one file, the entry chunk, by two lines** (`const FUSE_FORM_PX = {…}; Object.freeze(Object.keys(FUSE_FORM_PX));`), so the identity the executive table claims is guarded for this module only by a build nobody runs in CI. Smallest fix: add `[FUSE_LAYOUT, []]` to `REACHED` (the harness already makes `./fuseGeometry` external, so nothing else changes), a row asserting the unused bundle is empty and that only the entry and the module itself were loaded (no flag entry: this module never imports the flag module), and the plant above in "the row can fail". §4 confirms the fix on the pristine file and on the plant, whose leftovers are the call and the `FUSE_FORM_PX` table it drags with it.

**S2R-3 — A level live board: the hero crowns a seat while every form reads idle, and the clause that does it reads raw scores.**
`FuseHero.jsx:421`: the standing context's `shown` is false when every seat's running total is equal (`new Set(ids.map((id) => snap.values[id])).size > 1`), so every form is idle (`standingMood`, `leagueAgentMood.js:37`). But the hero's crown has no tie rule: `lead={d.seat.id === leaderId && !calm && !voided}` (`:431`) with `leaderId = deriveCut(…).ranked[0]` (`:202`), and `rankByScores` breaks a tie by seat order (`leagueTournament.js:925-929`), so a level board always crowns the first seat. The refuter (§4) rendered it: at 5 / 5 / 5 / 5, at 0 / 0 / 0 / 0, on a cold mount and on a trail with no head, the crown is drawn on seat `a` and every form, the crowned one included, is idle; when the player is the first seat, the player's own figure sits idle under its crown. And it is reachable every week: a pod's status flips to BATTLE before the open (`featureFlags.js:599-604`, `usePreOpenPhase.js`), `LEAGUE_FUSE_HERO_ENABLED` is true, and until the first sample every seat resolves to 0, so the shipped hero's first picture of every pod is a crown over an idle figure. Two rules break here. R15 says the standing comes from the screen's own order, never from raw scores and never with a new threshold: the level clause is a raw read of `snap.values` with a zero-margin threshold, the very margin S1's ruling 3 refused ("any lead counts"), and it sits in the same suite as the row that pins that ruling. BUILD_RULES §9 says a label and what it describes come from one source: the crown and the mood now have two. The report's justification, the climb's "at rest", is the all-zero case only (`ClimbArena.jsx:87`, whose comment rejects a bare tie on purpose), and the climb crowns at rest too (`:166`), so the climb inherits the same split, where the old head claimed nothing (`standing` 0 at rest). Flag on only. Smallest fix, by the letter: `shown: !calm && !voided`, the crown's own gate (one condition at `:421`, inside the flag's branch, so flag-off bytes are untouched); the two sites rows that pin the level case flip, and the report's "every seat level → Idle" (§7's table, and R15's mutant list) is reworded. The founder may instead ratify the level clause as an amendment to R15, since §7 presented it; then the crown is the thing to gate on a tie, which is a flag-off change and a separate ruling on the crown. Either way the two must share one gate.

**S2R-4 — Ruling 4's read pulls full completed documents, not "public agent context".**
