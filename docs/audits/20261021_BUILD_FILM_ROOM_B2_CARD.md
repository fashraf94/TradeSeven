## 8. Rulings asked (none blocks the merge; each is built one way and stated)

1. **RG-9, Set's route.** Set carries RG-5's sentence and the plain words "Which setting, and where you change it, is your call; this card links nowhere." The review (L1-8, L3-5; refuters R1 and R3) finds that the ONE player-settable input to `stalled` is the tempo dial (`TempoControl` on the Forge workshop's `CharacterArea.jsx`; `tapeTags.js` applies its multiplier to the forced-rotation ticks) — so RG-9's first branch (exactly one route → a link) may be the live one, except for an archetype whose stagnation rule is off (the threshold is then S2's checks and the dial never enters), where no route fits. A single static sentence cannot satisfy RG-9 across archetypes; the founder names the route (and whether it is archetype-conditional) and the screen pass links it.
2. **Recurrences on another battle.** A recurrence of THIS battle is a control that opens its day and jumps to the moment on this screen. A recurrence on ANOTHER battle is NAMED ("in another battle"), not linked: the App routes by state and has no route to another battle's Film Room (review L1-7, L3-4), so the earlier fragment link led nowhere. Wiring a cross-battle open is a follow-up (the hub or the screen pass).
3. **The note.** Length is counted in code points after trimming (an emoji is one character). A control character ANYWHERE in the trimmed note is refused, not stripped — every Unicode `Cc` character, C1 included (review L1-5 / L2-5), a newline included, by the strict reading of spec §4; trailing whitespace goes with the trim. An empty note is refused (`note_empty`): a card with no words would render an empty quotation.
4. **The counter's window.** Default: the last 120 calendar days of ET dates ending today — this build's own bounded read (ruling 18's "120 days of film" limits drills, not counting; the code comment was corrected, review R1-2) — floored at the earliest open Watch card's creation day, so a Watch card's recurrences are never cut by the default (review L1-2). A caller's `from`/`to` is honoured up to 400 days, and the floor stops there too: a Watch card older than 400 days lists only its last 400 days of recurrences. The founder may set both numbers.
10. **The tape's archetype against the agent's (review L1-1 / L5-1, MAJOR).** Spec §4's "the archetype it was created under" admits two readings: the agent's archetype at filing, or the tape day's (what the tagger stored, ruling 5's "earned on"). Built either way, a card filed from a day taped under another archetype than the agent's CURRENT one would be shelved at birth — never counted by S9, un-shelved en masse on a change back, with a receipt the player could not retire. This build REFUSES such a create (409 `archetype_changed`, the day's archetype and the agent's current one in the body; the screen says "The agent is on another archetype than this day's tape records. This card cannot be filed."), so a filed card's `archetypeCodeId` is both at once. The founder may relax it (file it shelved, or count shelved cards of that archetype against the cap); the refusal is one guarded line in `createCard`.
11. **An unavailable day that stores items (review L1-3).** The tagger can store items on a day whose checks section is partial (coverage.tags `unavailable`). The SCREEN now gives one answer across its regions: no rows in the prepared case and no tag line in the check detail. The ENDPOINT still accepts such a moment (spec §4's refusal list has no coverage clause) and the counter still counts the day. Whether the endpoint should refuse too is the founder's.
12. **`slotsVersion` (review L1-9b).** The ledger stores the slots module's version beside `situationVersion` and `questionVersion` — a written-once field spec §4's list does not name, by RG-8's rule that records keep the version they were written under. Declared here; the founder strikes it or adds it to §4.
13. **"Battle days since the card's date" (spec §6; review L3-11g).** The counter returns each recurrence with its day; it returns no count of battle days since the card, and the screen shows none. If §6 means a separate count, it is a counter field and a declared aggregate in the screen pass.
5. **Weekly counts are returned, not rendered.** The counter answers `weekly[agentId][situationId][monday] = { tags, moments }` (spec §5); the prompt's item 9 lists only recurrences and My cards for `since-last-time`, so the screen shows no weekly count in this build.

If the founder prefers derived for a code constant, both pins move together.
7. **The player's typed words.** The sweeps pass over the NOTE textarea's text (`[data-note]`; React renders a controlled textarea's value as its text child): the typed note is neither the screen's voice nor a stored record. Any other textarea, and a `<p>` beside it, is still swept (guard rows; review L3-9d).

The two agree by construction (the tagger copies the record into the item), so the fallback is unreachable on a tape the tagger wrote; it exists so a hand-edited tape never shows a number its path does not hold.
