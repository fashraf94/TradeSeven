## Activation blockers for the fix round

### B2-A01 · A previous session's last trade reserves new capital

On Monday 16 November the founder fixture held its three banks. The quote for MSFT contained a positive last trade of $420 with a truthful Friday 13 November, 16:00 ET timestamp. All held names had Monday quotes. The book's own mark classifier returned `carried_forward`. Shadow nevertheless saw MSFT under “last close”, proposed it for the long slot, and code admitted **$34,979.04**. This was an admission and treasury reservation. The next-session fill has its own price guard. The snapshot builder preserves the vendor timestamp but sets `complete` from the price alone. Both the prompt and admission candidate check use that weaker condition. (`api/_utils/mandateUniverseSnapshot.js:159`, `marks.js:123`, `agentSources.js:58`, `agentPrompt.js:147`, `agentRun.js:469`, `agentDrafting.js:129`, `admission.js:446`.)

**Bar (c).** A correctly timestamped last trade from an earlier session is sufficient. The provider can accurately report it, the model can choose an offered name, and one sequential fire reserves money for a name without a price from the judged session. Use the existing session-aware close-quality check in the shared candidate selector before offering or admitting a name. **Failing test.** Run `windowsAndClose` on D1 with `MSFT: {price: 420, at: etIso(DAYS.admit, 16, 0)}` and the other standard quotes, then draft MSFT for long. Expect it absent from the prompt, `name_not_a_candidate`, and the treasury and long slot unchanged. A current-session MSFT quote is the positive control. (`agentRun.test.js:34`, `agentRun.test.js:42`, `__testsupport__/fixtures.js:63`, `agentRun.test.js:509`, `marks.js:130`.)

### B2-A02 · A malformed draft lets the rest of its answer move money

Shadow sent an otherwise valid answer containing an exit for the founder's medium idea and a long MSFT draft with `comparison: {type: "same_stock_held", symbols: null}`. The tool declares an optional array. Its validator treats an explicit null as omission and drops the field. The answer was accepted as `model`, the medium idea became `settled` with `manager_exit`, and a **$34,979.04** long idea was admitted. The optional string `source.thesisRef` has the same null exception. R-4 requires whole-answer fallback for a field of the wrong type. (`agentTool.js:99`, `agentTool.js:118`, `agentTool.js:186`, `agentTool.js:201`, `agentTool.js:210`, `agentRun.js:388`, `agentRun.js:422`, `docs/audits/20261123_BUILD_B2_THE_AGENT.md:110`.)

**Bar (c).** An ordinary bad model answer changes exposure without a race or upstream fault. Enforce the declared types of optional properties whenever the raw tool object contains them, before normalizing the answer. **Failing test.** Send the combined exit and draft above. Expect one charged call, `source: code_fallback`, no manager endpoint, no admission and the same portfolio. Omit `symbols` altogether in the valid control. Add the analogous null `thesisRef` case to the same validation table. (`agentTool.js:173`, `agentTool.js:254`, `agentRun.test.js:101`, `agentRun.test.js:119`.)

### B2-A03 · A paid call and an admitted idea leave the window saying no model action

On the founder fixture, a successful Shadow response held the medium idea and admitted MSFT for long. The desk recorded `calledModel: true`, one settled $0.03 attempt and an admitted draft. The same close document still read **`modelCalled: false`, `outcome: "no_model_action"`**. The window ledger is defined to say whether the model ran and what it did. The founder CLI reads the nested desk data, which explains why its display can look correct while another reader of the same row sees the opposite. (`windowLedger.js:323`, `windowLedger.js:338`, `agentRun.js:104`, `agentRun.js:440`, `scripts/practice-field-founder.mjs:397`, `docs/design/20261113_PRACTICE_FIELD_AMENDMENT_C_GAME_AND_ACCOUNT.md:59`.)

**Bar (b).** A normal paid close produces the contradiction on the first day. Maintain the window-level call and action summary from both desks' recorded attempts and outcomes in the same close-row transaction. Preserve an earlier desk's work when the next desk records no work, and distinguish a paid fallback from an executed proposal. **Failing test.** Perform the hold-plus-admit above, then let the other desk finish and replay the close. Assert that the row records the call and admission, the count stays one for Shadow and a fresh paused control records zero calls. (`agentRun.js:196`, `agentRun.js:240`, `agentRun.js:404`, `agentRun.test.js:218`, `agentRun.test.js:483`.)
