## 1. Founder summary

**This audit does not support approving a broader release.** The checked-in database rules let an ordinary signed-in player overwrite other players' game records and read account email addresses and agent memory. Separately, server paths can be induced to attribute an attacker's battle to another agent, accept altered League scoring inputs, and start paid work without adequate authorization or durable quotas. These are supported source findings, with bounded local demonstrations; no claim is made that production currently exposes the identical configuration.

There are **six High and four Medium findings; no Critical finding is established**. Severity describes plausible harm under the stated prerequisites. Evidence status describes what was demonstrated, independently of severity.

| Priority | ID | Severity | Established behavior and practical consequence | Evidence status |
|---|---|---|---|---|
| 1 | F01 | High | Signed-in A overwrites B's game records; owners can edit all their profile fields. Results and progression cannot be trusted on these paths. | Reproduced locally: actual Firestore rules |
| 2 | F02 | High | Signed-in A reads/lists account emails and reads B's private agent memory/strategy. UI filtering does not protect the data. | Reproduced locally: actual Firestore rules |
| 3 | F03 | High | An extra agent `id` field survives server construction and directs battle completion at another agent's statistics. | Confirmed by code; rule and component reproductions |
| 4 | F04 | High | Anonymous POST skips GET-only job authentication; rankings starts 239 mocked provider requests. Other job guards also trust a caller-supplied cron marker. | Reproduced locally for method bypass; edge-header acceptance deployment-dependent |
| 5 | F08 | High | A player can overwrite a fresh League battle's starting prices and thresholds through an older API. | Reproduced locally: actual handler with mocked storage |
| 6 | F06 | High | Anonymous earnings verification repeatedly starts paid model/search work; an authenticated advisor caller controls its output ceiling. | Reproduced locally: actual handlers, mocked providers |
| 7 | F05 | Medium | Imported URLs reach server fetch without destination restrictions; private-address content can reach the model boundary. | Confirmed by code; request construction reproduced with mocked fetch |
| 8 | F10 | Medium | A shared parse cache ignores private note/user context, returning the first caller's context-dependent result to another caller. | Confirmed by code; seeded-cache reproduction; actual sensitive model output conditional |
| 9 | F07 | Medium | Two daily resets using the same old snapshot both add the same award. | Reproduced locally: actual writer, simulated database increments |
| 10 | F09 | Medium | API token validation does not request revocation/disabled-account checks, delaying containment of a still-valid stolen token. | Confirmed by code; SDK-call contract reproduced |

**Immediate recommendation, contingent on matching deployment evidence:** have the platform owner check deployed rules and routes first, restrict the affected database writes/reads, suspend public access to unnecessary job/legacy endpoints, and cap or temporarily gate anonymous paid verification. Preserve relevant logs and suspicious records before repair. These are recommendations, not actions taken in this audit. Do not assume changing the UI or tightening Firestore rules also protects privileged server writers.

Next, repair identity and scoring boundaries, introduce shared cost reservations, fix cache isolation and atomic daily awards, then verify revoked-session behavior. Required release evidence includes the actual deployed commit and rules; edge access policies for the affected routes; service-account permissions; real enforcement of provider/project spend caps; and successful regression/staging cases below. No production incident, stolen credential, account takeover, or dollar loss was demonstrated.

### F01 — Broad client write grants allow game-state corruption

**High · Reproduced locally · Ordinary signed-in account.** A player can modify another player's battle/draft/tournament document directly, regardless of screen controls, and edit arbitrary fields on their own user profile. Affected users are those whose records are in the broad collections; the operation is repeatable and can falsify status, scores, ownership, or progression. This is substantial integrity damage, without needing server credentials.

**Path and root cause:** unconditional signed-in create/update grants at [firestore.rules:98](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L98), [firestore.rules:177](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L177), [firestore.rules:501](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L501), [firestore.rules:509](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L509), [firestore.rules:517](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L517), [firestore.rules:746](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L746), [firestore.rules:754](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L754), and [firestore.rules:761](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L761). User updates check only matching UID at [firestore.rules:161](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L161). Real clients write game records through [src/firebase/firebaseService.js:243](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/src/firebase/firebaseService.js#L243) and [src/firebase/firebaseService.js:296](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/src/firebase/firebaseService.js#L296); default deny elsewhere does not override an explicit allow. Additional related surfaces include owner-unrestricted field sets in [firestore.rules:456](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L456) and bug-report/counter changes at [firestore.rules:785](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L785).

**Evidence:** [original rules-results.json evidence](2026-09-20_ASTRA_SECURITY_ABUSE_EVIDENCE.md#firestore-rules-assertions) records A changing B's synthetic status `active` to `completed`, score `0` to `99999`, and owner to A in nine collections: battles, trainingBattles, drafts, snakeDraftBattles, snakeDraftLobbies, challenges, earningsTournaments, optionsTournaments, draftAnalytics. A also writes its own stats/premium metadata. This proves field acceptance, not that a paid subscription is granted. Guest access was denied; deletes are often denied; neither protects these writes. **Fix / owner / effort:** backend + Firebase owner, approximately 3–5 days for an initial coherent rules/API boundary and tests; migrations may add work. Restrict client updates to explicitly permitted participant fields and transitions; make authoritative scores, price baselines, ownership, deadlines, and progression server-only. Audit each listed collection, including legacy ones. **Regression:** actual rules emulator rejects A's update to B and rejects protected-field updates by an owner while allowing each intended participant action. Recompute affected aggregates only after preserving evidence and establishing scope.

**High · Reproduced locally · Ordinary signed-in account.** A player can list account documents containing email addresses and read another agent's memory/directives, enabling privacy loss and strategy copying across accounts. There is no per-target relationship requirement in these grants.

**Path and root cause:** [firestore.rules:162](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L162) and [firestore.rules:225](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L225) grant full authenticated reads. UI owner filters in [src/services/agentService.js:16](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/src/services/agentService.js#L16) are not database authorization. [api/_utils/tournamentBattleView.js:5](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/api/_utils/tournamentBattleView.js#L5) explicitly describes hiding active strategy/WHY fields, making the privacy intent stronger than an assumption based on a field name.

**Evidence/protections:** A reads B's synthetic email and private memory/directives and lists users in the real-rules emulator. Separate public profiles/agent cards from private account and strategy documents; constrain reads/list queries to their intended audience. Firestore rules cannot redact selected fields from an allowed document read. **Regression:** A may fetch B's approved public card, cannot get/list B's private account/agent data, and owner dashboards/listeners still function.

### F03 — Stored agent `id` redirects server writes to another agent

**High · Confirmed by code; local rule and component demonstrations · Signed-in owner able to create an ordinary agent and deploy through the self-select path.** The attacker supplies their own legitimate owner field but adds `id` naming a victim agent. Server code trusts that extra field as canonical identity. The demonstrated consequence is cross-account statistics corruption, including a loss and negative score on B's agent.

**Complete source chain:** the create rule checks owner and numerous sensitive fields but not `id` ([firestore.rules:248](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L248), [firestore.rules:261](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/firestore.rules#L261)). The self-select route remains available ([api/agent/decide.js:311](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/api/agent/decide.js#L311)). Completion reads that target at [api/cron/agent-evaluate.js:4603](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/api/cron/agent-evaluate.js#L4603) and writes statistics at [api/cron/agent-evaluate.js:4798](https://github.com/fashraf94/TradeSeven/blob/0871937c9a12e7885ecfb08664f4f612b999d8a5/api/cron/agent-evaluate.js#L4798).
