A1. D9 — Superseded-attempt semantics, unified across paths (amends §4.5 step 4, §4.7, §6.1; r2: M1/m4 folded)
Founder ruling D9 (Jul 25): same-key receipt hits are handled by counting without classifying — the hash cannot carry classification for same-key mismatches, because retries regenerate (the DST double-fire re-runs the model; regeneration is non-deterministic; a legitimate retry hashes differently).
r2 unification (M1): the original A1 fixed the inline path and left the sweep asserting a certainty it doesn't have — a sweep replay of a failed regenerated retry carries a regenerated payload in its envelope, so a sweep-side same-key mismatch is the same unclassifiable event. The V1.5 tri-state's "conflict" class produced path-dependent labeling (benign / conflict / both, depending on failure timing) and a double-count on the cleanup-death straggler. Unified rule, both paths:

* On any same-key receipt hit: if `receipt.storyId === attempt.storyId` (hash necessarily matches — one hash per story, computed once) → completed (the post-commit race; clear + delete, nothing counted).
* Otherwise → superseded attempt: append the attempt's `storyId` to `receipt.supersededAttempts[]` if absent (inside the Wire transaction), stamp `wireSuperseded: true` on that story doc (own field, m4 — never `wireConflict`, which retires), clear `wirePending`, delete the envelope. No second entry, no receipt overwrite (B5 preserved in full).
* Counting is derived, exactly-once by construction: `validationStats.superseded` increments only on first append (membership check). The straggler path (transaction succeeded, cleanup died, sweep revisits) finds the storyId already in the list → pure no-op. No event can be counted twice or labeled two ways.
* `idempotencyConflicts` retires from stats, code, and the §6.1 gate. The scenario it protected against — a key-minting bug collapsing two genuinely different events onto one key — surfaces the same way A1 catches everything: superseded counts on non-DST, non-retry days require explanation at the gate. DST-day counts are self-explaining.
* §6.1 gate line (replaces the conflicts line): `superseded` reviewed; nonzero on DST transition days expected; nonzero otherwise requires explanation.
* Spec-text clarification: F2-10's "matching" = same idempotency key; B5's "no-op, not a repair" governs what is never overwritten. The key is the trigger-slot identity; any same-key surplus is a surplus attempt at the same logical event, whatever generated it.
* Tests (required): inline regenerated mismatch → superseded path (list append, stamp, count once); sweep replay of a failed regenerated retry → superseded, not conflict (the M1 case); straggler revisit → no-op, count unchanged; derived-count exactness under the full matrix.

A2. `subjectRef` (amends §4.1, §4.4, templates; r2: M2/m7 + A4 tie folded)
Defect: `econ_print`/`econ_preview`/`index_move` digests cannot name their own subject; all three are macro-eligible — exactly what Phase 3's pre-market scan consumes. C3's fix worsened indices (SPX-family symbols are not `TICKER_TO_SECTOR` keys → bare-noun fallback).
Design — split by who determines the subject, with the asymmetry now justified (M2):

* Neta's seams (`econ_print`, `econ_preview`): SERVER-STAMPED. The trigger determines the subject: `canonicalizeEconEvent` maps the trigger's event name pre-call. `PersistedAgentFacts.subjectRef` = uppercased known slug (`CPI, PPI, NFP, FOMC, PCE, GDP, RETAIL_SALES, JOBLESS_CLAIMS, ISM_MFG, ISM_SVC`) or `null` on unknown alias (degradation unchanged). `ModelAgentFacts` untouched for Neta. A4 tie (r2): Neta's pinned schemas exclude `subjectRef` entirely — server-owned, the model never sees the field.
* `index_move` (Kai): MODEL-EMITTED, required — justified by discovery fact: Kai's idempotency key is `kai:pulse:{period}` — a time-slot trigger carrying no symbol; the pulse surveys the whole market and the model selects which index to headline. There is nothing for the server to stamp from. Closed enum `{SPX, NDX, DJI, RUT, VIX}`; missing or out-of-enum on an `index_move` → R4 REJECT (subject-less index events are unusable).
* Internal-consistency check (r2, M2): new ETF→index map (`SPY→SPX, QQQ→NDX, DIA→DJI, IWM→RUT`). When the model's `primaryTicker` maps and disagrees with its `subjectRef` → SALVAGE: `subjectRef` remapped to the mapped value, class `S1_SUBJECT_REMAPPED`. Unmappable/absent `primaryTicker` → `subjectRef` stands as emitted. This catches internal inconsistency, not truth.
* Known limitation (r2, m7): an enum-valid-but-wrong subject with no mappable cross-check is structurally uncatchable by the validator — acknowledged, not silently untested. `index_move` joins the Phase 2 editorial stratified sampling explicitly for subject correctness.
* Conditional-required mechanics (r2, M2): `subjectRef` is an optional property in Kai's multi-eventType schema. Validator: required for `index_move` (missing → R4); present on any other row → SALVAGE-drop (invalid optional field for that row, consistent with existing tiering).
* Templates lead with the subject (`"CPI print: +0.2pp vs expected."` / `"NDX move: −1.2% vs prior close."`); `null` renders the current generic form.
* Correction of record (unchanged from r1): the earlier claim that `subjectRef` improves Neta's idempotency key was wrong — B5 mints keys pre-call; no model-emitted field can reach a key. Known-alias events now carry a deterministic server subject; unknown-alias key behavior is unchanged.
* Tests (required): server stamp known/unknown alias; Neta pinned schemas reject/omit the field; `index_move` missing/out-of-enum → R4; `S1_SUBJECT_REMAPPED` fixture (SPY + subjectRef NDX → SPX); subjectRef on `technical_break` → SALVAGE-drop; template fixtures ×3 incl. `null` form. Wrong-subject-unmappable: acknowledged untestable at the validator (m7); editorial-sampled.

A3. `figures[]` sign consistency — narrow rule (amends §4.4; r2: m5 folded)
A `figures[]` entry whose `basis` is identical to the basis carrying the row's `direction` subject must be sign-consistent with `direction`; all other figure bases are unconstrained (reversal narratives — `direction: up` with a negative `gap_vs_prior_close` — remain legal). Scope (r2, m5): the rule applies only when `direction ∈ {up, down}`; `mixed` and `flat` rows are exempt (sign-matching is undefined for mixed and vacuous for flat). Violation is R4-class. Tests: same-basis inconsistency rejects; differing-basis counter-directional passes; flat-direction same-basis figure passes (exemption).
