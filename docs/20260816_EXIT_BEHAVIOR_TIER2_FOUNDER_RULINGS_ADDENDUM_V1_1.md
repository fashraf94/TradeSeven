## R11 (Phase-0 #2) — User-directive deterministic orders fire through gameplan suppression; fix the guardrail-tier placement in Ask 3

**Finding:** guardrail stops (`guardrail_stopLoss`/`guardrail_trailingStop` — the user's equipped stops) are silently suppressed on every tick a gameplan meeting is pending-and-unexpired, because `applyGuardrails`'s sole call site (`agent-evaluate.js:2065`) sits downstream of the gameplan early-returns (`:1803`, `:1831`). Risk-manager stops (`:1371`) fire upstream and are unaffected. This is a pre-existing §9 violation on the stop's own promise — "hard, enforced," except during meetings.

**Ruling:** the principle from F12 decides it — suppression governs discretionary trading, never the user's standing deterministic orders. A stop or target firing mid-meeting is not the agent trading; it is the engine honoring the user's directive.

- The build hoists the user-directive deterministic class (existing guardrail stops + the new profit target) above the gameplan gate, alongside/adjacent to the risk-manager tier.
- Red-first test: stop breach during a pending-unexpired gameplan window → fires (RED today), plus the equivalent for the target.
- This deliberately widens Ask 3 to touch live stop behavior. It gets its own adversarial attention in the §7 review: the hoist must not change stop semantics (thresholds, LOCK deference, replacement path) — only when in the tick they are checked. Non-suppression ticks must produce byte-identical stop outcomes (test).
- The rejected alternative is recorded: shipping the target with promise text "…except during gameplan meetings" perpetuates the defect with disclosure as a fig leaf.

## R12 (Phase-0 #6) — Contrarian restore grounded; add the held-position Levels render (data-add #3)

**Finding:** the resistance read is real (`findNearestLevels` → `nearestResistance`, ≥2-touch swing clusters, conditionally populated) but renders only on bench-candidate lines (`agentEvalPromptAssembly.js:1410-1414`) — while the Contrarian's profit-taking-into-resistance applies to held positions.

**Ruling:** restore per R7, and add data-add #3: render the Levels line (nearestSupport/nearestResistance where present) for held positions in the eval context — non-fenced assembly work, staged with Ask 1's other data-adds. Stance wording handles the null case honestly ("when a resistance read is present"); no wording may imply an always-available signal.

## R13 (Phase-0 #8) — Target replacement path: `pickSwapReplacementCandidate`, full stop

**Ruling:** the target's forced-swap replacement is resolved via `pickSwapReplacementCandidate` (held-excluding, cooldown-aware, quality-predicate seam, clean-null veto) — the same live path the risk and guardrail tiers use. `pickEmergencyReplacement` is dead (zero live callers, negative regression test at `agent-evaluate.test.js:310`), held-blind, and modeling on it reintroduces the June-11 LRCX self-swap / PANW triple-slot bug class. No revival. Removing the dead function is separate hygiene, not this build. Clean-null behavior = the F2 promise's "fires at the first evaluation a replacement becomes eligible."

## Banked build hazards (verified, binding on the spec)

- **Entry baseline (Phase-0 #4):** the target computes gain against `getEntryPrice` (`swapPrice ‖ startingPrice` — Gain-since-entry), never daily `changePercent`. The short-sign residual is moot for this executor (the league agent side is long-only by game design) — noted, not solved.
- **LOCK ordering (Phase-0 #3):** the target defers on the agent bonus-proximity LOCK exactly as guardrail stops do (`blocked_by_lock` passthrough), per R6. Bust/vwap outranking LOCK is existing protective behavior and stays. The LOCK respected is the agent risk LOCK, not any user-layer flag — promise text should not imply otherwise.
- **Keyed-list data-adds (Phase-0 #7, #1):** `guardrail_profitTarget` → `RECEIPT_EXIT_REASONS` (validity) + `DETERMINISTIC_LABELS` (ledger label, e.g. "profit target") + the Tier-1 contract test amended in the same PR (R3). It stays OUT of `D3_DISCRETIONARY_EXIT_REASONS` (R4). Source stays `'guardrail'` (already a member; already stamped by the existing ternary).
- **Distance-to-threshold (Phase-0 #5) = data-add #1:** an always-present per-position "Δ to next bonus" column needs a fresh compute (next uncrossed threshold − current multiplier, × baseATR) — `detectRedZone`/band math is proximity-banded and returns null outside its bands; do not reuse as-is. Staged with Ask 1.
- **Gameplan exit literal:** approved-gameplan swaps stamp `exitReason:'gameplan_rotation'` — existing, unaffected; listed so nobody "unifies" it into the new class.
