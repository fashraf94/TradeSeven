## 1. What the idea book is, under the Charter

The Practice Field's idea book (concept V6.1) is a paper portfolio the player's agent fills and manages. Its records are **forward observations**: what the agent expected, what it did, what happened. Using the originating archetype's private observations to draft later ideas is **experience-informed adaptation**. It is not a Charter-qualified lesson, not model-weight training, and not evidence of a repeatable advantage.

## 2. What the Charter's mechanism clauses mean for it

| Charter clause | Application |
|---|---|
| §3 M1 episode grain, M2 one-step counterfactuals, M3 policies not trades, M4 batch mining | These govern the Charter's historical game-counterfactual miner. A forward paper run is a separate, explicitly typed observational path. It is not an M2 one-step replay and inherits none of M2's proof status. Branching retrospective simulations remain outside M2 |
| §2 epistemic split: deterministic code settles outcomes | Holds. Code settles every idea's contract condition and economic result. The agent proposes, manages within enforced limits and explains; its interpretation is shown as unverified |
| §4 claim territories | A portfolio idea is not a claim territory. Release 1 adopts only **player instructions** (equipping an idea and its list), which the Charter already permits; it claims no learned strategy |
| §4 platform-level aggregation (T3) | Does **not** authorise exporting idea-book experience. Private observations, drafts, results and adopted changes stay with the originating player and archetype instance, never aggregated across users or archetypes, with or without names |
| §2 bar on per-user market-alpha promotion | Stands. No idea-book result promotes a private market-alpha claim to a strategy |
| Risk-exit protection rule (§4, the protection-value requirement) | Governs any offset or hedging experiment: avoided-loss and forgone-upside evidence including tails; never a removal rule based on net cost alone |
| Development and confirmation (Amendment A, A5) | Any claim of improvement, including a lean, dial, bundle or rule version tested in a release 2 branch book, keeps development evidence apart from confirmation evidence under a frozen candidate |

## 3. The one exception to "nothing reaches a prompt before installed"

The idea book's manager may read its own frozen settings snapshot and book state; the drafting call may read the player's own sources, this archetype's completed ideas and a versioned methods packet. That exception grants no access to the deployed agent's battle or draft prompts, memory or consolidation, nor to any other player's or archetype's records. Shared contract V2 §9 fixes the access and the negative tests.

## 4. What this addendum does not do

It does not add a claim type, change a maturity gate, or weaken any promotion rule. New market-alpha claim types, if ever wanted, require an explicit Charter revision, not an inference from this addendum.
