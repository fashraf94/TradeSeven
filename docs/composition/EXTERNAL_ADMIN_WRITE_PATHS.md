# External Admin Write Paths — Operational Inventory (B8-FINAL)

**What this is:** the B8-FINAL operational inventory of every write path into the protected identity stores (`agents`, `rules`/`bundles` subcollections, `compiledBuilds`, `composition*`) that **cannot be code-fenced** — no epoch helper, lease, or rules clause can intercept it. Each path gets an explicit **out-of-band pause step** in the §8 window and a **verify step** at close. The census (`compositionWriterCensus.json`) covers the in-code writers; this document covers everything that writes from OUTSIDE the code the census can see.

**Rule of use:** the ACTIVATION_RUNBOOK's epoch-close step is not complete until every row below is confirmed paused, and its unfreeze step is not complete until every row is confirmed resumed.

| # | Path | Who can invoke | What it can write | PAUSE step (§8 window) | VERIFY step |
|---|---|---|---|---|---|
| E1 | **Firebase Console — manual document edits** | Project owners/editors (founder) | Any document, any collection, silently | Nobody edits documents in the Console during the window — the runbook operator confirms the checklist line "Console untouched" at close; second person not required (solo-founder project) but the line is signed | The B8 watermark scan (post-close `updateTime` sweep over protected collections) shows zero non-runbook writes in the window |
| E2 | **firebase CLI / gcloud with owner credentials** (`firebase firestore:delete`, imports, `gcloud firestore` ops) | Anyone holding owner/service-account keys (founder's machine) | Bulk reads/writes/deletes, index changes | No `firebase`/`gcloud` firestore commands during the window except the runbook's own scripted steps (each named in the runbook log) | Same watermark sweep; the runbook log names every sanctioned CLI invocation with its timestamp |
| E3 | **Repo admin CLI scripts run by hand with service-account creds** — `scripts/rule-compat-cleanup.js`, `scripts/mastery-preflip-normalize.js`, `scripts/ws1-observe-walk.js`, `api/scripts/migrate-*.js` (census `adminCliScripts` rows) | Founder / any operator with the service key | The exact protected stores (censused per script) | These scripts DO carry the in-code guard (`assertWriteEpochOpen` / lease), so a closed epoch rejects them — the pause step is still explicit: **do not invoke** during the window; the guard is the backstop, not the plan | The scripts' own epoch rejection (`epoch_closed`) if invoked; watermark sweep as the second belt |
| E4 | **`scripts/composition/migration-scan.js --apply`** | Runbook operator only | `compositionCandidateState` + overlay entries | NOT paused — this IS a runbook step; it runs exactly once at its step number, epoch-fenced in code | The apply report + zero-residual scan are the runbook's own verification |
| E5 | **Service accounts held by Vercel** (production env: the deployed API + crons) | The deployed code only | Whatever the deployed endpoints/crons write | Not an admin path in itself (the census + fence govern the code) — but a **stale Vercel deployment** predating the fence is: the runbook's step-0 SHA check (`preflight-at-sha.js --sha <deployed>`) proves the deployed SHA carries the census-green fence before the close begins | Vercel deployment SHA recorded in the runbook log; step-0 preflight report at that SHA |
| E6 | **Firestore emulator / local dev against production creds** (misconfigured `.env` pointing a local run at prod) | Any developer machine holding prod keys | Anything the local code writes | Standing rule (not window-scoped): local runs use the emulator project id; during the window, no local server runs with prod creds — checklist line | Watermark sweep; prod key inventory (one key, founder's machine) |

**Honest boundary:** rows E1/E2/E6 are *procedural* controls — nothing in code can stop an owner credential. The auditable guarantee is the **post-close watermark sweep** (B8): every protected-store document whose `updateTime` falls inside the closed window must be attributable to a named runbook step, or the activation does not proceed.
