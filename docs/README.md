# FantasyTrades — Governing Documents (`docs/`)

This directory is the version-controlled source of truth for the League Tournament build and the contracts that govern it. It exists because the June 10 implementation discovery was blocked by exactly one thing: none of these documents lived in the repo. Every implementation chat reads from here, not from pasted context.

## Reading order for an implementation session

1. **`BUILD_RULES.md`** — the operating rules. Read first, always. (Also referenced from the repo-root `CLAUDE.md` so Claude Code loads it automatically.)
2. **`FANTASYTRADES_LEAGUE_TOURNAMENT_IMPLEMENTATION_SPEC_V1.md`** — the binding build spec. Where it differs from the framework, the spec wins; its §0 decisions register is the delta log.
3. **`FANTASYTRADES_LEAGUE_TOURNAMENT_DESIGN_FRAMEWORK_V2_1_AGENTIC.md`** — the design of record (the *why* behind the spec).
4. **`audits/2026-06-10_IMPLEMENTATION_DISCOVERY.md`** — the citation baseline for the build (file:line anchors, fence-contact register, verdicts).
5. As needed: the remaining documents below.

True regeneration of any record from model memory remains forbidden: if a record is missing, report it, don't reconstruct it.

## Maintenance rules

- Documents here are **records**, not living files: superseding happens by adding a new versioned document, never by editing a locked one. (Exception: this README's table and `BUILD_RULES.md`, which track current state.)
- Audit reports are immutable once added — their line anchors are tied to the HEAD they name.
- When a build phase changes a rule of record (e.g., a fence change), `BUILD_RULES.md` is updated **in the same PR**, with the founder decision cited.
