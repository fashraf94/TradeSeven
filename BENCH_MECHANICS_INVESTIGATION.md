# Bench Mechanics Investigation

**Scope**: Read-only investigation of how the bench (`battle.portfolio.bench`) functions in the FantasyTrades codebase today. No design recommendations, no proposed changes — only how it currently works, with concrete file:line references.

**Why**: Scoping for Layer 1 Phase 3 (live intraday VWAP and 5-min SMA20 overlay). Currently `api/cron/agent-evaluate.js` computes intraday momentum only for portfolio symbols — bench symbols don't get intraday data. Before deciding whether Phase 3 should extend intraday coverage to bench, we need a complete picture of how bench actually works. Findings also serve Sprint 2 and Tier 1 follow-on work.

---

## 1. Bench Composition at Battle Start

### 1.1 Code path

Battle creation flows through three steps:

1. **Agent deploys via `/api/agent/decide`** — Haiku constructs the portfolio (including bench) using the `PORTFOLIO_TOOL` tool schema and writes the result to `agent.lastDecision`.
2. **The decide endpoint then calls `createAgentBattle()`** — `api/agent/decide.js:439-463` (battle creation entry).
3. **`createAgentBattle()` reads `lastDecision.bench` and embeds it into the new battle document** — `api/_utils/agentBattleService.js:42-101`.

```javascript
// api/_utils/agentBattleService.js:47-48
const portfolio = agentData.lastDecision?.portfolio;
const bench = agentData.lastDecision?.bench;
```

```javascript
// api/_utils/agentBattleService.js:90-101
portfolio: {
  star: deepCopyArrayWithSector(portfolio.star, sectorMap),
  core: deepCopyArrayWithSector(portfolio.core, sectorMap),
  support: deepCopyArrayWithSector(portfolio.support, sectorMap),
  bench: {
    stocks: deepCopyArrayWithSector(bench?.stocks, sectorMap),
    crypto: bench?.crypto ? { ...bench.crypto, sector: sectorMap[bench.crypto.symbol] || (bench.crypto.isCrypto ? 'Crypto' : 'Unknown') } : null,
  },
  startingPrices: { ...startingPrices },
},
```

### 1.2 Origin of bench entries

**Stocks**: agent-generated by Haiku via the `PORTFOLIO_TOOL` schema. Not user-selected.

```javascript
// api/_utils/agentToolSchema.js:79-90
bench_stocks: {
  type: 'array',
  items: { type: 'string' },
  minItems: 3,
  maxItems: 3,
  description: 'Exactly 3 stock tickers for bench (swap reserves)',
},
bench_crypto: {
  type: 'string',
  description: 'Exactly 1 crypto symbol for bench (different from support_crypto)',
},
```

**Crypto**: also agent-generated, single slot, must differ from `support_crypto` (validated at `decide.js:556-558`).

**Source pool**: Haiku selects bench picks from the same archetype-ranked stock universe / shortlist used for star/core/support. Symbols are then enriched into asset objects via `enrichPortfolio` / `toAsset`:

```javascript
// api/agent/decide.js:609-644
function enrichPortfolio(result, stockUniverse) {
  const lookup = {};
  stockUniverse.forEach((s) => { lookup[s.symbol] = s; });

  const toAsset = (symbol) => {
    const stock = lookup[symbol];
    if (stock) {
      return {
        symbol,
        name: stock.name || symbol,
        baseATR: (stock.atrPercentile || 0.5) * 8,
        isCrypto: false,
      };
    }
    const crypto = getCryptoBySymbol(symbol);
    if (crypto) return { ...crypto };
    return { symbol, name: symbol, baseATR: 3.0, isCrypto: false };
  };

  return {
    portfolio: { star: ..., core: ..., support: ... },
    bench: {
      stocks: result.bench_stocks.map(toAsset),
      crypto: toAsset(result.bench_crypto),
    },
  };
}
```

### 1.3 Constraints

- **Bench size: fixed**. Exactly 3 stocks (`minItems: 3, maxItems: 3` in PORTFOLIO_TOOL) and exactly 1 crypto. Not a range, not unbounded.
- **No portfolio↔bench symbol overlap**. Validated at `api/agent/decide.js:550-558`:
  ```javascript
  // Check duplicates
  const allSymbols = [...allStocks, result.support_crypto, result.bench_crypto].filter(Boolean);
  const unique = new Set(allSymbols);
  if (unique.size !== allSymbols.length) errors.push('Duplicate symbols detected');
  // Check crypto are different
  if (result.support_crypto && result.support_crypto === result.bench_crypto) {
    errors.push('Support and bench crypto must be different');
  }
  ```
- **No explicit sector limits or sector diversification rules** for bench. Sector is *attached* at battle creation via the `sectorMap` parameter (`agentBattleService.js:97`), but there is no constraint that bench has to span N sectors or avoid duplicate sectors.
- **Archetype influence is upstream, not on the bench itself**. `ARCHETYPE_WEIGHTS` (`api/_utils/archetypeScoring.js:14-93`) shape the ranked stock universe Haiku draws from, so an aggressive-momentum agent's shortlist tilts toward high-RS/high-ATR names. But there is no archetype-specific *bench rule* — Haiku's bench picks just inherit whatever the shortlist contains.
- **No cooldown rule at creation**. `cooldownUntil` is set only when an asset is benched via swap (see Q2). Initial bench has no cooldown flags.

## 2. Bench Updates During a Battle

### 2.1 Persistent writers

There is **exactly one persistent writer** that mutates `battle.portfolio.bench.*` after battle creation:

**`api/_utils/agentSwapExecution.js:101-256` — `executeSwapServer`**, the transactional swap handler. The relevant Firestore update:

```javascript
// api/_utils/agentSwapExecution.js:242-252
const updates = {
  [`portfolio.${resolvedTier}`]: newTier,
  [`portfolio.bench.stocks`]: updatedBenchStocks,
  [`portfolio.bench.crypto`]: updatedBenchCrypto,
  thresholdHistory: newThresholdHistory,
  trades,
  [`scoreState.tradeCount`]: (liveData.scoreState?.tradeCount || 0) + 1,
  updatedAt: now,
};
transaction.update(battleRef, updates);
```

There are also two **in-memory-only** mutations during `agent-evaluate.js` that are *never persisted* — they exist purely to make symbols available to Haiku for that single eval tick:

- **HotBench merge** — `api/cron/agent-evaluate.js:454-471`. Top candidates from the daily `stockRankings` that match `watchlist.hotBench` are spliced into `battle.portfolio.bench.stocks` for the Haiku prompt only:
  ```javascript
  // api/cron/agent-evaluate.js:466-471
  if (Object.keys(hotBenchAssetMap).length > 0) {
    const originalBenchStocks = battle.portfolio?.bench?.stocks || [];
    battle.portfolio.bench.stocks = [
      ...originalBenchStocks,
      ...Object.values(hotBenchAssetMap),
    ];
  }
  ```
- **Catalyst override** — `api/cron/agent-evaluate.js:728`. News-tagged tickers are pushed into bench in-memory:
  ```javascript
  battle.portfolio.bench.stocks.push(hotBenchAssetMap[ticker]);
  ```

Neither of these in-memory expansions hits Firestore. They mutate the in-process `battle` object so Haiku sees the symbols, then are discarded.

### 2.2 Trigger for the persistent writer

`executeSwapServer` is called when a swap decision is committed. Three call sites:

- **Risk-triggered swaps** — emergency swaps enforced by the risk manager (`api/_utils/agentRiskManager.js`) when an asset breaches stop-loss or trail-stop.
- **Haiku-decided swaps** — when Haiku returns a `swap` action via the `TRADE_DECISION_TOOL`.
- **Guardrail-enforced swaps** — when Haiku's decision is downgraded by deployed-strategy guardrails.

All three flow through `executeSwapServer`. There is no time-based cron job that rebalances bench on its own. **Bench is event-driven, not schedule-driven.**

### 2.3 Swap mechanics — the "revolving door"

The full bench mutation logic, labeled in-source as "Amendment 6":

```javascript
// api/_utils/agentSwapExecution.js:210-237
// ---- Revolving door bench (Amendment 6) ----
const outgoingForBench = {
  symbol: outAsset.symbol,
  name: outAsset.name || outAsset.symbol,
  baseATR: outAsset.baseATR,
  isCrypto: outAsset.isCrypto || false,
  direction: outAsset.direction || null,
  cooldownUntil: new Date(Date.now() + 24 * 60 * 60 * 1000).toISOString(),
};

let updatedBenchStocks;
let updatedBenchCrypto;

if (outAsset.isCrypto) {
  // Crypto swap: outgoing crypto goes to bench.crypto, remove incoming from bench
  updatedBenchStocks = (liveData.portfolio.bench?.stocks || []).filter(s => s.symbol !== inSymbol);
  updatedBenchCrypto = outgoingForBench;
} else {
  // Stock swap: outgoing stock added to bench.stocks, remove incoming
  updatedBenchStocks = (liveData.portfolio.bench?.stocks || [])
    .filter(s => s.symbol !== inSymbol)
    .concat([outgoingForBench]);
  // If bench crypto was the incoming asset, clear it
  updatedBenchCrypto = liveData.portfolio.bench?.crypto?.symbol === inSymbol
    ? null
    : (liveData.portfolio.bench?.crypto || null);
}
```

So:

- **Portfolio → bench (a position being benched)**: outgoing asset is appended to `bench.stocks` (or set as `bench.crypto` if crypto) with `cooldownUntil = now + 24h`.
- **Bench → portfolio (a swap-in)**: incoming symbol is removed from bench (`.filter(s => s.symbol !== inSymbol)`). It does not stay on bench.
- **Cooldown enforcement**: an asset on cooldown cannot be swapped back in. Validated at `agentSwapExecution.js:36-48`:
  ```javascript
  const benchAsset = findAssetInBench(battle.portfolio?.bench, decision.symbolIn);
  const hotBenchMatch = !benchAsset && (battle.watchlist?.hotBench || []).includes(decision.symbolIn);
  if (!benchAsset && !hotBenchMatch) {
    errors.push(`symbolIn "${decision.symbolIn}" not found in bench or watchlist`);
  }
  if (benchAsset?.cooldownUntil) {
    const cooldownEnd = new Date(benchAsset.cooldownUntil);
    if (cooldownEnd > new Date()) {
      errors.push(`symbolIn "${decision.symbolIn}" is on 24h cooldown until ${benchAsset.cooldownUntil}`);
    }
  }
  ```

### 2.4 Bench size dynamics

- Starts at 3 stocks + 1 crypto.
- Each swap removes one entry (incoming) and adds one entry (outgoing). On a single-asset swap, the count stays the same.
- However, the outgoing asset was a *portfolio* slot, not a *bench* slot — so on a stock swap, bench grows by +1 (incoming removed; outgoing added). The portfolio slot is replaced 1:1.
- Wait — re-reading more carefully: incoming is removed from bench (-1), outgoing is appended to bench (+1). Net: bench size unchanged. Portfolio: outgoing asset moved out of its slot, incoming asset takes that slot. Portfolio size unchanged.
- **There is no automatic replenishment from a wider universe.** If bench shrinks (e.g., crypto swapped out and bench crypto absorbed elsewhere), nothing repopulates it.

**Explicit answer**: Bench is **not static after creation** — it mutates on every swap event via the revolving-door rule, and 24h cooldowns are stamped onto benched-out assets.

## 3. Haiku + Bench in Execution Decisions

### 3.1 Cron schedule and trigger gating

Cron schedule (`api/cron/agent-evaluate.js:6`):

```
*/15 13,14,15,16,17,18,19,20,21 * * 1-5
```

Every 15 min, 13:00–21:00 UTC (covers 9:30–17:00 ET market hours plus surrounding bands), weekdays only.

**Haiku is not called every tick.** A trigger gate decides:

```javascript
// api/cron/agent-evaluate.js:750
const { shouldEvaluate, triggers, newStoryIds } = evaluateTriggers(
  battle, assetScores, prices, news, momentumData, seenStoryIds
);
```

If `shouldEvaluate === false`, only scores are updated; Haiku is not invoked.

The gate (`api/_utils/agentTriggerGate.js:20-184`) checks 9 categories:
1. `forced_open` (first eval of battle) — `agentTriggerGate.js:27-30`
2. `forced_close` (final hour) — `agentTriggerGate.js:33-37`
3. `price_drop` (active asset down >0.5x ATR) — `agentTriggerGate.js:42-49`
4. `threshold_proximity` (within 0.2x ATR of bonus/penalty threshold) — `agentTriggerGate.js:52-88`
5. `bench_outperformance` — see below
6. `vwap_deviation` (intraday VWAP deviation ≥1.5%) — `agentTriggerGate.js:115-130`
7. `bandwidth_squeeze` (Bollinger BW <20th pct)
8. `nr7_contraction`
9. `news_catalyst` (FantasyTimes story on portfolio ticker)

**Bench-driven trigger** — `api/_utils/agentTriggerGate.js:90-113`:

```javascript
// Bench outperformance: bench stock up > 0.5x ATR today while an active asset is flat/down
const benchAssets = flattenBenchServer(battle.portfolio?.bench);
const hasWeakActive = assetScores.some(s => s.priceChange <= 0);

if (hasWeakActive) {
  for (const benchAsset of benchAssets) {
    if (benchAsset.cooldownUntil && new Date(benchAsset.cooldownUntil) > new Date()) continue;
    const benchPrice = prices[benchAsset.symbol];
    if (!benchPrice) continue;
    const dailyChangePct = benchPrice.changePercent || 0;
    const benchATR = benchAsset.baseATR || 2.5;
    const benchATRMult = dailyChangePct / benchATR;
    if (benchATRMult >= 0.5) {
      triggers.push({
        type: 'bench_outperformance',
        detail: `${benchAsset.symbol} up ${dailyChangePct.toFixed(2)}% today (${benchATRMult.toFixed(2)}x ATR from daily open)`,
      });
    }
  }
}
```

Note: the bench trigger is computed from **daily** `changePercent` and `baseATR`, not intraday data.

### 3.2 Where bench enters Haiku's prompt

The live context block is built at `agent-evaluate.js:796-799`:

```javascript
await buildLiveContextBlock(
  battle, prices, macroPrices, assetScores,
  triggers, news, battle.evaluations, momentumData, presetConfig
),
```

Inside, bench is rendered to a CSV by `buildBenchCSV` — `api/_utils/agentEvalPromptAssembly.js:873-901`:

```javascript
function buildBenchCSV(bench, prices) {
  if (!bench) return 'BENCH: Empty — no stocks available for swap.';
  const allBench = flattenBenchServer(bench);
  if (allBench.length === 0) return 'BENCH: Empty — no stocks available for swap.';
  const header = 'BENCH (available for swap):\nSymbol,Sector,$Current,Daily%,ATR%,Status';
  const now = new Date();
  const rows = allBench.map(asset => {
    const price = prices[asset.symbol];
    const currentPrice = price?.current || 0;
    const dailyPct = price?.changePercent || 0;
    const atr = asset.baseATR || 2.5;
    const sector = asset.sector || 'Unknown';
    let status = 'available';
    if (asset.cooldownUntil) {
      const cooldownEnd = new Date(asset.cooldownUntil);
      if (cooldownEnd > now) {
        status = `locked until ${asset.cooldownUntil}`;
      }
    }
    return `${asset.symbol},${sector},$${currentPrice.toFixed(2)},${formatPct(dailyPct)}%,${atr.toFixed(1)}%,${status}`;
  });
  return [header, ...rows].join('\n');
}
```

So the per-symbol fields Haiku sees for **each bench candidate** are:
- Symbol
- Sector
- Current price
- Daily % change
- ATR % (volatility band)
- Status (`available` or `locked until <ISO timestamp>`)

That's it. No intraday data, no relative-strength percentile, no MACD, no RSI, no VWAP, no Bollinger Band width. Daily-only.

### 3.3 Replacement source: bench-only

When Haiku decides to swap, the replacement (`symbolIn`) **must be in bench** (or in `watchlist.hotBench`, which is in-memory merged into bench for that tick). There is no universe fallback inside Haiku's allowed choices. This is enforced at swap-validation time:

```javascript
// api/_utils/agentSwapExecution.js:36-41
const benchAsset = findAssetInBench(battle.portfolio?.bench, decision.symbolIn);
const hotBenchMatch = !benchAsset && (battle.watchlist?.hotBench || []).includes(decision.symbolIn);
if (!benchAsset && !hotBenchMatch) {
  errors.push(`symbolIn "${decision.symbolIn}" not found in bench or watchlist`);
}
```

The hotBench merge (`agent-evaluate.js:454-471`) effectively expands bench at evaluation time with daily-ranking-driven candidates, but Haiku still cannot reach into the full universe ad-hoc.

### 3.4 Ranking among bench candidates

There is **no explicit per-candidate scoring or ranking step** for bench in code. Haiku is given the bench CSV as a flat table and ranks implicitly via prompt reasoning, guided by system-prompt directives (`api/_utils/agentEvalPromptAssembly.js:41-88`) that include "RELATIVE STRENGTH" framing and "SECTOR AWARENESS" guidance (e.g., rotate into a different sector for diversification when swapping).

There is no code that pre-sorts bench candidates by score or ranks them quantitatively before Haiku sees them.

### 3.5 Data parity: bench vs portfolio

Active portfolio symbols receive considerably richer context than bench symbols today:

| Data type | Active portfolio | Bench |
|---|---|---|
| Daily price + % change | Yes (in liveContext + buildPortfolioCSV) | Yes (buildBenchCSV) |
| Sector | Yes | Yes |
| Baseline ATR | Yes | Yes |
| Cooldown status | n/a | Yes (`status` column) |
| Intraday VWAP | Yes (when present in `momentumData.vwap`) | **No** — `momentumData` is fetched per `portfolioSymbols` only at `agent-evaluate.js:354-379` |
| Bollinger Band width / NR7 | Yes (`momentumData.rankings`) | No |
| Asset-level scoring (multiplier, badges, score deltas) | Yes (`calculateAssetScoreServer`) | No — scoring runs on portfolio only |
| Institutional intelligence | Yes (where pre-computed) | Bench symbols can be added dynamically (via hotBench), but institutional pre-compute is portfolio-symbol-driven (`agentEvalPromptAssembly.js:376-419`) |

**This is the precise data-parity gap relevant to Phase 3 scoping.** Bench currently sees only daily metrics; the intraday momentum bundle (VWAP, 5-min SMA20, RSI, BB width, NR7) is not computed for bench symbols.

## 4. User Vision + Bench

### 4.1 Vision input path

Vision is captured in the frontend, not via a chat API endpoint. Important to disambiguate **vision** from **directive**:

- **Directive** = short tactical guidance from the user, captured by `api/agent/chat.js:280-393` and stored on `battle.directive`. This is *not* vision.
- **Vision** = the strategic thesis (state machine: `unformed → proposed → active → under_debate → stale → retired`), structured under `battle.vision`. Persisted via Firestore writes from the React app (`src/firebase/firebaseService.js:240` calls `createInitialVision` at battle creation; state transitions managed via `src/types/vision/visionTransitions.js` + `src/types/vision/visionValidators.js`).

Searching `/api` for vision write paths returns essentially one persistent writer:

```
api/cron/agent-evaluate.js:1666     updatePayload.vision = retiredVisionForWrite;
api/_utils/visionRuntime.js:34       case 'vision':              # filterActiveConstraints — read-only
api/cron/agent-evaluate.js:512       const vision = battle?.vision ?? null;   # read for prompt
```

The api side never *creates* or *transitions* vision through user input — it only reads vision into the Haiku prompt and retires it on battle end.

### 4.3 Does vision affect bench?

**No.** Searching the codebase, there is no code that:

- Filters bench by vision direction or scope
- Reweights or reranks bench candidates based on vision drivers
- Triggers bench regeneration on a vision state transition
- Modifies the bench-outperformance trigger using vision

Bench is mutated only by `executeSwapServer` (a swap event) and merged in-memory by hotBench / catalyst override (both vision-agnostic). No vision-aware bench-writer exists in the codebase.

Vision IS visible to Haiku at swap-decision time (via `buildVisionStateBlock` in the prompt, with text "Your tactical decisions must be coherent with this Vision"). So vision can influence which bench candidates Haiku *picks*, but it does not influence which symbols are *available* in bench.

**Explicit answer**: Vision doesn't currently affect bench composition. Vision affects Haiku's *reasoning over the existing bench*, not the *contents* of the bench.

### 4.4 Note on directive

The chat-endpoint "directive" feature (`api/agent/chat.js`) similarly does not affect bench composition. Directives are stored on `battle.directive` and on `agent.directives[]` (`chat.js:369-393`); they are read into the Haiku prompt as guidance but do not mutate bench.

## 5. Bench's Relationship to Other Surfaces

### 5.1 Scout alerts

Scout alerts are **sourced from `watchlist.active`, not from bench**. From `api/cron/voice-layer-cache.js:374-434`:

```javascript
function buildScoutAlerts(watchlist, rankingsMap, techScoresMap, archetype, portfolioSymbols) {
  if (!watchlist?.active) return [];
  const alerts = [];
  watchlist.active.forEach(entry => {
    const symbol = entry?.symbol || entry;
    if (!symbol || typeof symbol !== 'string') return;
    if (portfolioSymbols.has(symbol)) return;
    // ... rs_breakout / volume_surge / game_fit alert builders
  });
  // Filter by archetype relevance, cap at 5
  return filtered.slice(0, 5);
}
```

The exclusion filter only removes *active portfolio* symbols (`portfolioSymbols.has(symbol)`). Bench symbols are not on `portfolioSymbols`, so a bench symbol could appear in scout alerts *if* it also lives in `watchlist.active` — but bench and `watchlist.active` are independent surfaces in the data model, and scout alert sourcing is decoupled from bench by design.

### 5.2 Index Intelligence rankings

Bench candidates get **no special treatment** in `compute-index-intelligence.js`. Rankings (`stockRankings`) are computed across the universe; there is no bench-aware boost or filter. Each stock entry contains technicalScore, technicalRank, fundamentalRank, compositeScore, baggerBombFit, and archetype scores — all archetype-/score-driven, not bench-aware (`api/cron/compute-index-intelligence.js:718-804`).

The `voice-layer-cache.js` bench briefs read from the same `rankingsMap` and `techScoresMap` as portfolio briefs, so bench symbols inherit whatever score they happen to have, but receive no priority surfacing.

### 5.3 Forge rules / archetype scoring

Archetype influences bench only through the **upstream stock universe** Haiku draws from when it builds a portfolio. From `api/_utils/archetypeScoring.js:14-93`, `ARCHETYPE_WEIGHTS` shape the scoring of candidates:

```javascript
export const ARCHETYPE_WEIGHTS = {
  momentum_chaser: {
    fundamentalScore: 0.05,
    technicalScore: 0.40,
    baggerBombFit: 0.30,
    atrPercentile: 0.25,
  },
  analyst: {
    fundamentalScore: 0.40,
    technicalScore: 0.30,
    // ...
  },
  // ...
};
```

So a `momentum_chaser` agent gets a shortlist tilted toward high-RS, high-ATR names — and its bench picks fall out of that tilt — but there is no "archetype filter" applied directly to bench, and no logic that rebalances bench based on archetype mid-battle.

### 5.4 Sprint 1 outputs (consolidatedInsight, convictions, lessons)

These do **not** flow into bench composition or bench-related decisions today.

- `consolidatedInsight` is injected into the Voice Layer prompt as strategic wisdom (`api/_utils/agentPromptAssembly.js:108-111`):
  ```javascript
  if (agent.consolidatedInsight) {
    parts.push(
      `STRATEGIC WISDOM (from ${agent.evolutionCycle || 0} evolution cycles):\n${agent.consolidatedInsight}`
    );
  }
  ```
- It is also frozen onto the battle at creation (`agentBattleService.js:128`).
- Lessons / convictions / disciplines are processed in `agentConsolidationApply.js` to update agent strategy state — none of this reads or writes `portfolio.bench`.

These outputs influence agent strategy and Voice Layer messaging, not bench selection or rotation.

### 5.5 Other consumers of bench data

The bench data flows are:

**Writers**:
- `executeSwapServer` (`agentSwapExecution.js:242-252`) — only persistent writer.
- `agent-evaluate.js:454-471` and `:728` — in-memory only, never persisted.

**Readers**:
- **Voice Layer cache** (`api/cron/voice-layer-cache.js:253-368`) — `buildBenchBriefs` reads `battle.portfolio.bench` and produces `benchBriefs[]` with: `symbol, assetClass, price, changePercent, technicalScore, technicalRank, rsPercentile, sector, cooldownUntil, cooldownActive, atrPercent, trendSummary?, momentumSummary?`. ## Synthesis

**Bench in FantasyTrades today functions as a closed, agent-generated reserve of swap candidates with revolving-door semantics, daily-only data richness, and no vision-driven re-composition.**

### Key facts

- **Initial composition**: fixed at 3 stocks + 1 crypto. Agent-generated by Haiku via `PORTFOLIO_TOOL` from the archetype-weighted shortlist. Not user-selected.
- **Constraints at creation**: no portfolio↔bench overlap; no sector limits; no archetype-specific bench rule (only the upstream shortlist is archetype-tilted).
- **Mutations during battle**: only `executeSwapServer` (in `agentSwapExecution.js`) writes bench to Firestore. Triggered by swap events (risk, Haiku, guardrail) — never by a scheduled cron. Revolving-door rule: incoming asset removed from bench, outgoing asset added with 24h cooldown. There is no auto-replenishment from a wider universe.
- **Two in-memory bench expansions** at eval time (hotBench, catalyst override) make universe candidates visible to Haiku without persisting them.
- **Haiku data shape for bench**: per-symbol CSV with symbol, sector, $current, daily%, ATR%, status. Daily-only. No intraday momentum (VWAP, 5-min SMA20, RSI, BB, NR7), no per-asset score, no institutional context.
- **Replacement source**: bench-only (plus hotBench in-memory). Haiku cannot reach into the full universe ad-hoc; swap validation rejects symbols not in bench or watchlist.hotBench.
- **No explicit ranking step**. Haiku ranks bench candidates implicitly via prompt reasoning.
- **Trigger frequency**: Haiku is gated. Cron tick is 15 min during market hours, but Haiku is invoked only when ≥1 of 9 trigger categories fires. The bench-driven trigger (`bench_outperformance`) uses daily change vs. baseATR — not intraday.
- **Vision and bench are decoupled**. Vision is read into the Haiku prompt and retired by cron at battle end; vision state never mutates, regenerates, or reweights bench. Vision can only influence which bench candidate Haiku *picks*, not which symbols are *on* bench.
- **Other surfaces**: scout alerts source from `watchlist.active`, not bench. Rankings have no bench-specific boost. Sprint 1 outputs (consolidatedInsight, lessons) feed strategy/Voice Layer, not bench. Bench briefs flow into the Voice Layer cache and are consumed by the chat prompt; UI reads bench from Firestore directly.

### Notable findings worth surfacing for design decisions

1. **The bench data-parity gap is concrete and isolated.** Haiku evaluates bench candidates with strictly less data than active positions — daily-only, no intraday. This is the precise gap relevant to the Phase 3 scoping question. The `bench_outperformance` trigger today uses daily `changePercent / baseATR`, so it only fires on end-of-day-sized moves, not intraday breakouts.
2. **The hotBench in-memory expansion is significant.** `agent-evaluate.js:454-471` already gives Haiku visibility into universe stocks beyond the persisted bench, without persistence. This is an existing escape valve that may interact with any decision to expand bench data coverage.
3. **The catalyst override path** (`agent-evaluate.js:728`) is another in-memory bench expansion driven by news. It also uses no intraday context.
4. **Vision and bench are not coupled in the current design.** Vision is rendered as advisory text in the Haiku prompt, not as a filter on candidate selection. If a design discussion considers vision-driven bench composition, that would be a new coupling.
5. **Scout alerts and bench are decoupled surfaces.** They draw from different watchlist fields (`watchlist.active` vs `battle.portfolio.bench`). They are not a shared candidate pool.
6. **The revolving-door rule means bench can drift from its initial archetype tilt over time** as benched-out assets accumulate. The shortlist that produced the original bench is not consulted again; bench composition is a function of swap history after the first swap.
7. **The 24h cooldown is hardcoded** at `agentSwapExecution.js:217`. It is the only protection against immediate ping-pong swaps.
8. **Bench briefs in the Voice Layer cache do carry richer data than the Haiku CSV** (technicalScore, rsPercentile, atrPercent, trend/momentum summaries — `voice-layer-cache.js:253-368`). The Voice Layer chat agent has access to richer bench context than the Haiku trade agent does. This asymmetry is worth noting.
9. **There is no documented automatic refresh of bench composition** based on changing universe rankings. The daily ranking refresh affects `watchlist.hotBench` (which Haiku can access via in-memory merge), but not the persisted bench itself.
10. **I cannot determine from the codebase whether `watchlist.hotBench` is refreshed by an explicit cron job.** The reference in `agent-evaluate.js:454` reads `hotBench` from `battle.watchlist`; the writer for `watchlist.hotBench` was not surfaced in this investigation. (Worth a follow-up if hotBench dynamics matter for a design decision.)
