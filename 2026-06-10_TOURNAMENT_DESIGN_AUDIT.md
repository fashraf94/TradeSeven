3. Priority 1 — GO/NO-GO statement
The double-down mechanic is NOT viable against current position-state modeling. NO-GO without changes to fenced files.

What does NOT break it: the portfolio itself. Positions are plain array elements in portfolio.star[]/core[]/support[] (api/_utils/agentBattleService.js:90-101), every scoring loop iterates entries not symbols (api/_utils/agentScoring.js:43-58; api/cron/agent-evaluate.js:307-356), and per-entry base points sum independently (agent-evaluate.js:409). Structurally, two entries with the same symbol can exist and earn base points independently.

What breaks it — the exact structures:

thresholdHistory is a symbol-keyed map (agentBattleService.js:186; read at agent-evaluate.js:315,352; written by dot-path thresholdHistory.<symbol> at agent-evaluate.js:441-443 — two same-symbol scores write the same key, last write wins). Badge state is shared: if one copy crosses a Bagger threshold, the other copy reads the shared maxMultiplier and is paid the same badge bonus on its own entry (agentScoring.js:277-287) → one threshold crossing pays twice; the nightly banking has the same double-pay shape (api/cron/agent-daily-scores.js:120-132).
Swap-in resets the shared history. executeSwapServer unconditionally zeroes thresholdHistory[inSymbol] (agentSwapExecution.js:266-272) — swapping a duplicate IN wipes the other copy's earned badge progress. Bench updates also filter all entries of that symbol (agentSwapExecution.js:289, 293-295).
Swap-out targeting is first-match-by-symbol. findAssetInPortfolio (agentSwapExecution.js:328-341) and findPortfolioSlot (api/_utils/agentRiskManager.js:430-443, used at agent-evaluate.js:839, 1892) return the first slot in star→core→support order. With a user-layer AAPL and an agent-layer AAPL, an agent-initiated exit of "AAPL" resolves to whichever slot is listed first — a risk stop on the agent's copy can land on the user's locked copy. This is where double-down and the lock seam collide head-on.
Risk counters are symbol-keyed AND incremented per entry. cronState.vwapTicks/stagnationTicks/lastTickPrice/lastTickTimestamp are {symbol: value} maps (agent-evaluate.js:694-701); the loop runs once per position entry (:717), so a doubled symbol increments the shared VWAP counter twice per tick (:724-728) — a 2-tick VWAP-failure threshold fires in one tick — and the second stagnation update compares against a lastTickPrice the first update just wrote (:735-746), inflating the counter. riskStatus[symbol] overwrites (:763); lockedPositions is a symbol Set (:693, 768-770) — a LOCK on one copy locks both.
Deploy validator rejects duplicates outright. validatePortfolio errors with 'Duplicate symbols detected' across the full selection (decide.js:722-725); the swap path, by contrast, has no uniqueness check on symbolIn (agentSwapExecution.js:39-44) — today uniqueness is an emergent property of candidate-pool filters that exclude held symbols (decide.js:362-364; agent-evaluate.js:511-513, 596, 983-987; agentRiskManager.js:395-399), not of any validator.
Entry baselines degrade to shared state after a daily reset. Per-position swapPrice differentiates duplicate entries, but the nightly cron deletes it (agent-daily-scores.js:158-168), after which entry price falls back to the symbol-keyed portfolio.startingPrices[symbol] (agent-evaluate.js:309; agentBattleService.js:100) — a swapped-in duplicate inherits the other copy's baseline. (Single-day battles mask this; weekly battles would not.)
Guardrail trailing stops read the shared peak. Implied peak is derived from thresholdHistory[symbol].maxMultiplier (api/_utils/agentGuardrails.js:386-391) — a doubled symbol gets one peak for two different entries.
Duplicate-tolerant subsystems, for completeness: trades[] records carry tier + slotIndex (agentSwapExecution.js:223-241) — position-specific and unambiguous; scoring.thresholds[symbol] is shared but value-identical for the same symbol (benign — decide.js:584-592); pure price lookups prices[symbol] are market data, not position state (agent-evaluate.js:266-285).

Deploy-time duplicate rejection. The design treats duplicates as load-bearing; validatePortfolio explicitly errors 'Duplicate symbols detected' across the agent's entire 13-asset selection (decide.js:722-725). The agent layer cannot even duplicate itself at deploy, let alone the user layer, as built.
Claim execution drifts an hour with DST. The cron is pinned at 25 14 * * 1-5 UTC (vercel.json:58-59). 14:25 UTC = 9:25 AM ET only under EST; under EDT (mid-March–early-November, i.e., now) it is 10:25 AM ET — ~55 minutes after open, while the client window still closes at 9:24 AM ET (claimFreeAgencyService.js:44-47, 95). "Executes ~5 minutes before open" is a winter-only truth; claims currently execute against nearly an hour of live price action in summer.
